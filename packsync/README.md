# packsync/ — механизм автосинхронизации

Эта папка **не входит в индекс packwiz** (см. `.packwizignore`), но CI раскладывает
её внутрь всех публикуемых артефактов:

| Артефакт | Куда попадает |
|---|---|
| zip-инстанс для Prism / Freesm | `minecraft/packsync/` |
| `.mrpack` для AstralRinth / Modrinth App | `overrides/packsync/` |

То есть у игрока она оказывается в **корне папки игры** — `<папка игры>/packsync/`.

## Файлы

| Файл | Назначение |
|---|---|
| `packwiz-installer-bootstrap.jar` | Загрузчик (v0.0.3, MIT). Умеет сам обновлять installer; мы это отключаем флагом `--bootstrap-no-update`, чтобы версия была зафиксирована и запуск не зависел от GitHub API. |
| `packwiz-installer.jar` | Сам синхронизатор (v0.5.14, MIT). Читает `pack.toml` + `index.toml` по HTTP, сверяет хэши и докачивает только изменившееся. |
| `sync.cmd` | Обёртка для Windows. Ищет `java.exe` и запускает синхронизацию. **Всегда возвращает код 0**, чтобы сбой синхронизации не блокировал запуск игры. |
| `sync.sh` | То же для Linux / macOS. |
| `pack-url.txt` | Единственная строка — адрес `pack.toml` на GitHub Pages. CI перезаписывает его автоматически. |
| `LICENSE-packwiz-installer.txt` | Лицензия MIT на оба jar-файла. |

## Почему обёртки, а не прямая команда

В **Prism Launcher / Freesm** pre-launch command умеет кавычки и переменные,
поэтому там прописывается полная команда с `$INST_JAVA` и `$INST_DIR` (CI делает это само).

В **AstralRinth / Modrinth App** hook выполняется иначе: строка режется по пробелам
и запускается напрямую, **без shell, без кавычек и без подстановки переменных**
(рабочая папка = папка инстанса). Поэтому туда подходит только короткая команда
без пробелов в аргументах:

```
Windows :  cmd /c packsync\sync.cmd
Linux   :  sh packsync/sync.sh
```

Вся логика поиска Java спрятана внутри скриптов.

## Обновление версии packwiz-installer

1. Скачайте новый jar:
   `https://github.com/packwiz/packwiz-installer/releases`
2. Замените `packwiz-installer.jar`, обновите номер версии в `LICENSE-packwiz-installer.txt`.
3. Закоммитьте и запушьте — CI подхватит автоматически.

Игроки получат новый jar при следующем импорте пака (в уже установленных
инстансах jar не перезаписывается намеренно — иначе он блокировался бы во время работы).
