# Modpack Manager — приложение для проверки и починки сборки

Оконное приложение на чистом **PowerShell 5.1 + WinForms**. Зависимостей нет:
работает на любой Windows 10/11 из коробки, ничего ставить не нужно.

`ModpackManager.ps1` — само приложение. `ModpackManager.bat` — обёртка для
двойного клика (добавляет `-STA` и обход ExecutionPolicy).

---

## Зачем оно нужно, если синхронизация и так автоматическая

Синхронизация при запуске игры идёт через `packwiz-installer` с флагом `-g`,
то есть **молча**. Когда что-то идёт не так, игрок видит просто «модов нет»,
и непонятно: hook не прописан, Java не нашлась, сервер недоступен, файл побился
или мод отключён вручную.

Приложение отвечает на этот вопрос за пару секунд и **чинит** то, что можно
починить, — причём собственным загрузчиком, без Java.

---

## Что делает

### Выбор папки сборки

Кнопка **«Обзор…»** или выпадающий список. Список заполняется автоматически
перебором известных расположений:

| Лаунчер | Где ищем |
|---|---|
| AstralRinth | `%APPDATA%\AstralRinthApp\profiles\<имя>` |
| Modrinth App | `%APPDATA%\ModrinthApp\profiles\<имя>` |
| Freesm Launcher | `%APPDATA%\FreesmLauncher\instances\<имя>\.minecraft` |
| Prism Launcher | `%APPDATA%\PrismLauncher\instances\<имя>\.minecraft` |
| MultiMC | `%APPDATA%\MultiMC\instances\<имя>\.minecraft` |
| Ванильный | `%APPDATA%\.minecraft` |

Разница принципиальная: у Theseus-лаунчеров (AstralRinth, Modrinth App) папка
профиля **и есть** папка игры, а у Prism-семейства игра лежит в подпапке
`.minecraft`. Функция `Get-PrismGameDir` это учитывает.

В списке первыми идут папки, где уже есть `packsync/`; остальные помечаются
`— нет packsync` или `— пустой инстанс`, чтобы было видно, где пак не установлен.

Выбранная папка, адрес пака, сторона и список недавних сохраняются в
`%LOCALAPPDATA%\ModpackManager\settings.json`.

### Проверка

Адрес пака берётся из `<папка сборки>\packsync\pack-url.txt`, поэтому приложение
всегда проверяет против того сервера, на который настроен этот инстанс. Можно
переопределить вручную в поле «Адрес пака».

Дальше повторяется **та же цепочка, что у `packwiz-installer`**:

```
pack.toml   -> имя пака, версия MC и загрузчика, sha256 индекса
index.toml  -> список всех файлов пака с хэшами (sha256 сверяется с pack.toml)
mods/*.pw.toml -> для каждого мода: URL на Modrinth, sha1, side
каждый файл -> сравнение с диском ПО ХЭШУ
```

Проверяются не только моды, но и всё остальное содержимое пака: `config/`,
`defaultconfigs/`, `kubejs/`, `resourcepacks/`, `shaderpacks/` и любые прочие
файлы. Они раскладываются по вкладкам:

| Вкладка | Что там |
|---|---|
| **Моды** | записи из `mods/*.pw.toml` |
| **Конфиги и файлы** | всё остальное содержимое пака, сгруппированное по категориям |
| **Лишние** | файлы в `mods/`, `config/`, `resourcepacks/`, `shaderpacks/`, которых нет в паке |
| **Журнал** | что и когда делало приложение, ошибки закачки |

### Статусы

| Статус | Значение | Чинится? |
|---|---|---|
| `НА МЕСТЕ` | файл есть и хэш совпал | — |
| `ОТСУТСТВУЕТ` | файла нет | да, скачает |
| `НЕ СОВПАДАЕТ` | файл есть, хэш другой (битый или старый) | да, заменит |
| `ОТКЛЮЧЁН` | лежит как `<имя>.disabled` | нет — это сделал игрок |
| `НЕТ (preserve)` | в `index.toml` стоит `preserve = true` | нет — намеренно |
| `ДРУГАЯ СТОРОНА` | мод серверный, а выбрана сторона `client` | нет |
| `ЛИШНИЙ` | файла нет в паке | да, если попросить |

`preserve = true` — важный случай: так помечают файлы, которые нельзя
перезаписывать (например `options.txt`), чтобы не затирать личные настройки
игрока. Приложение показывает их отдельным статусом, а не как ошибку.

### Починка

**Собственный загрузчик на PowerShell** (`Invoke-WebRequest`), Java не нужна:

1. скачивает во временный `<файл>.download`;
2. считает хэш скачанного и сверяет с ожидаемым — **битый файл не подменяет хороший**;
3. только после успешной проверки делает `Move-Item -Force`;
4. заменяемый файл предварительно копируется в `.modpack-backup\`.

Можно чинить всё сразу или только выделенные строки (в таблице работает
мультивыделение). Прогресс — в статус-баре.

**«Убрать лишние файлы»** показывает список и переносит их в `.modpack-backup`,
а не удаляет навсегда.

## Меню

| Меню | Пункты |
|---|---|
| **Файл** | Выбрать папку сборки… · Недавние · Сохранить отчёт… (txt/csv) · Выход |
| **Проверка** | Проверить сейчас · Проверить, игнорируя сторону |
| **Синхронизация** | Починить всё · Починить только выбранное · Убрать лишние файлы… · Запустить packwiz-installer (через Java)… |
| **Инструменты** | Открыть `mods/` · Открыть `config/` · Открыть папку сборки · Открыть `sync.log` · Показывать окно прогресса при запуске игры (`SHOW_GUI`) · Открыть папку бэкапов |
| **Справка** | О программе · Как это работает · Показать адрес пака |

Пункт **«Запустить packwiz-installer (через Java)»** оставлен намеренно: это
запуск штатного `packsync\sync.cmd`. Нужен, когда хочется сравнить поведение
собственного загрузчика приложения и штатного механизма.

Пункт **`SHOW_GUI`** создаёт/удаляет файл `packsync\SHOW_GUI`. Пока он есть,
синхронизация при запуске игры идёт **без** `-g` — с видимым окном прогресса
`packwiz-installer`. Это самый быстрый способ понять, качается ли что-нибудь
вообще, не открывая приложение.

## Запуск

```powershell
# одной командой, без скачивания файлов
$b='https://yungspiderq.github.io/my-neoforge-pack'
irm $b/ModpackManager.ps1 -OutFile $env:TEMP\ModpackManager.ps1
powershell -ExecutionPolicy Bypass -STA -File $env:TEMP\ModpackManager.ps1
```

```powershell
# параметры
powershell -ExecutionPolicy Bypass -STA -File ModpackManager.ps1 `
    -GameDir "$env:APPDATA\AstralRinthApp\profiles\MyPack" `
    -BaseUrl https://user.github.io/repo `
    -Side server
```

`-STA` обязателен: WinForms не работает в multi-threaded apartment.

---

## Границы

Приложение **не запускает игру и не трогает аккаунты** — это инструмент
обслуживания сборки. Запуск по-прежнему делает лаунчер, в котором уже
настроена авторизация.

База данных лаунчера (`app.db` у AstralRinth) не читается и не пишется:
прописывать hook в чужую SQLite — неоправданный риск, поэтому он остаётся
ручным (4 клика, строка уже копируется в буфер установщиком).

## Кроссплатформенный аналог

То же самое без Windows — `scripts/verify.py`:

```bash
python scripts/verify.py --game-dir "$HOME/.local/share/astralrinth/profiles/MyPack"
```

Он дополнительно проверяет доступность `latest/instance.zip` и `latest/pack.mrpack`
и корректность `PreLaunchCommand` внутри них. Код возврата ненулевой при любом
провале, поэтому его удобно гонять в CI.
